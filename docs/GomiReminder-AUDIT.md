# コード健康診断（2026-10-23）

## 今回の全体監査で修正した点

- アプリ復帰のたびに全アラームを作り直していた処理を廃止。更新後の一度、通知が再び許可された時、正確なアラーム権限の取り消し時だけ自己修復。
- 正確なアラーム権限の前回状態をSharedPreferencesへ保存。Androidが権限取り消し時にアプリを停止しても、次回起動で通常アラームへ復旧できるよう修正。
- 正確なアラーム権限の「許可」時はシステムBroadcast側で再構築し、画面復帰との二重処理を抑制。
- 「出した / 今回は通知不要」を押してもトップ画面・収集カード・ウィジェットが今回分を表示し続ける状態を修正。次の未処理収集へ進むよう変更。
- アプリを開いたまま通知アクションを押した場合も、画面が古いまま残らないよう、画面生存中だけ完了状態のSharedPreferences変更イベントを監視。ポーリングは追加していない。
- 古い通知アクションの有効性確認前に現在の通知を消していた順序を修正。過去・無効な操作が新しい通知へ干渉しない。
- 古いスヌーズBroadcastが遅れて届いた場合、新しく設定した30分後状態まで消さないよう、収集日一致時だけスヌーズ状態を消費。
- 再起動・権限復旧が前日通知時刻から2時間以上後だと今回分を捨てていた固定2時間制限を廃止。前日通知は日付変更まで、朝通知は設定時刻から3時間まで救済。
- 通知時刻にOS設定で通知を出せなかった場合、その状態を保存。後で通知を再許可してアプリへ戻った時、前日なら日付変更まで・朝なら設定時刻から3時間以内の今回分を救済。
- 1件編集するだけで全収集ルールを再予約していた処理を縮小。通知条件が変わったIDだけを再予約。
- 名前・地域だけの編集ではAlarmManagerを触らないよう変更。
- 名前・地域編集で無関係な30分後スヌーズまで消えていた干渉を解消。
- 例外日などを編集しただけで、まだ有効な「出した / 今回は通知不要 / 通知済み」状態まで消える問題を修正。
- 30分後スヌーズは新ルールでも対象日が有効なら維持し、無効になった場合だけ予約と状態を削除。
- 「出した / 今回は通知不要」後の全再構築でも、今回分を再予約しないよう抑止状態をスケジューラ側でも判定。
- 削除・バックアップ復元で同じアラームを二重キャンセルしていた経路を一本化。
- 旧版の重複IDや削除済みIDに紐づく孤児アラーム・一時状態を掃除。
- 再起動・時刻変更Receiverをコンポーネントごと無効化する過剰最適化を撤回。低頻度のOSイベントは確実に受け、有効な収集ルールがなければ即終了する単純な方式へ変更。
- 通知Receiverのウィジェット更新は毎回行わず、「出した / 今回は通知不要」で表示内容が変わる時だけ実行。
- ウィジェットを2時間周期まで間引くと日付変更後に表示が長く古いままになるため、OSがサポートする30分周期へ戻した。ウィジェット未配置時には周期更新されない。設定変更時は即時更新を維持。
- ウィジェットを小型スマホ向けに140dp × 64dpまで縮小可能に調整。
- 壊れたSharedPreferencesの収集日JSONを空配列へ自己修復し、同じ解析失敗を毎回繰り返さないよう修正。
- 壊れたスヌーズ状態を検出した場合、そのキーを自動削除。
- 「完了 / 今回不要」の重複判定をAppPreferencesへ集約。
- 収集ルール判定を `matches` / `matchesRule` に分離し、ON/OFFを除いた日付判定の重複を削減。
- 正確なアラーム可否判定をAlarmSchedulerへ集約。
- Gradle起動スクリプトはバージョン・SHA値を `gradle-wrapper.properties` から読むよう統一。
- API 36、AGP 8.10.1、Gradle 8.11.1、JDK 17の組み合わせを維持。
- `LocalLifecycleOwner` はCompose UI側の互換エイリアスに依存せず、`lifecycle-runtime-compose` を明示依存して正規APIへ統一。将来のCompose更新でのビルド破損リスクを低減。

## 既に対策済みの重要事項

- 旧版と現行版のUI・機能経路を突き合わせ、前日通知、朝通知、30分後、今回不要、例外日、複数地域、カレンダー、ウィジェット、編集、バックアップの入口と処理本体が残っていることを再確認。

- 通知権限だけでなく、アプリ全体・通知チャンネルOFFも検出。
- exact alarm設定中の権限競合は通常アラームへフォールバック。
- 過去日の通知アクションを無効化。
- 「出した / 今回は通知不要」と30分後の競合で通知が復活しないよう防止。
- 同一収集ルールの重複登録防止・旧重複データ統合。
- 収集なし日と振替収集日の同日競合を防止。
- 復元前の設定を部分適用しないJSON検証。
- Android標準自動バックアップとアプリ内JSONの二重管理を廃止。

## 検査結果

- XML全ファイル: 構文解析OK
- `gradlew`: shell構文OK
- Kotlin全ソース: Android/Compose依存を除いた構文チェックで構文エラーなし
- `Models.kt`: 実コンパイル＋2024〜2032年の日付スモークテストOK
- TODO / FIXME / NotImplementedError: なし
- 常駐Service / WorkManager / Timer / 独自ポーリング / 動的registerReceiver: なし
- Android依存を含むAPK最終ビルド: 実行環境にAndroid SDKがなく、さらに `services.gradle.org` をDNS解決できないため未実行
- `./gradlew --version`: スクリプトは起動し、Gradle取得時のDNS解決で停止。コード由来のGradle構文エラーではない

## OS仕様として残る制限

- 正確なアラーム権限をOS側で取り消すと、既存の正確なアラームがAndroidにより取り消される場合がある。取り消しBroadcastは送られないため、アプリを次に前面へ戻した時点で通常アラームへ自己修復する。
- アプリの強制停止、メーカー独自の強い省電力、OSによる通知完全OFFはアプリ側から回避できない。
- ウィジェットの周期更新時刻はランチャー / OSが調整するため厳密な30分ではない。
