# ゴミ通知リマインダー

地域ごとのごみ収集日を登録し、前日と当日の朝に知らせるAndroidアプリです。小さなスマートフォンでも使いやすいよう、トップ画面は「次のゴミの日」を優先し、詳細設定は必要なときだけ開く構成です。

## 主な機能

- 複数地域・複数ごみ種類の登録
- 毎週の複数曜日、第1〜第5、最終曜日の指定
- 前日通知と当日朝通知、通知時刻の変更
- 通知から「出した」「30分後」「今回は通知不要」
- 祝日・年末年始の収集なし日、振替収集日
- 次回収集日、7日 / 1か月予定
- 収集ルールの編集、ON/OFF、削除確認、重複登録防止
- ホーム画面ウィジェット
- JSONバックアップ / 復元
- 再起動、時刻・タイムゾーン変更、アプリ更新後の再予約

## 通知設計

- Android 13以降は初回起動時に通知権限を要求します。
- Android 12以降は「アラームとリマインダー」の特別アクセスを初回に案内します。未許可でも通常アラームへフォールバックするため、アプリ自体は利用できます。
- 「出した」「今回は通知不要」は今回の収集分だけを抑止し、次回収集分には影響しません。
- 30分後通知は、収集ルール変更後も対象日が有効なら維持し、対象日が無効になった場合だけ取り消します。
- 同じ収集分について「出した / 今回は通知不要」と30分後が競合しても、完了状態を再確認して再通知しません。
- 過去日の通知アクションは無効化します。
- 正確なアラーム権限が途中で外れた場合は、次回アプリ復帰時に通常アラームへ自己修復します。

## 無駄なバックグラウンド処理の抑制

常駐Service、ポーリング、タイマー監視は使っていません。

- 通知はAlarmManagerで必要な時刻だけ予約
- 再起動・時刻変更などを受けるReceiverは、有効な収集ルールがある時だけ有効化
- アプリ復帰時は権限状態が変わった場合だけ必要な再構築を実行
- 収集ルール編集時は、曜日・例外日・ON/OFFなど通知条件が変わったIDだけ再予約
- 名前・地域だけの編集ではAlarmManagerを触らない
- ウィジェットはOS管理の2時間周期に加え、設定変更時に即時更新

## バックアップ

Storage Access Frameworkを使用するため、ストレージ全体への権限は不要です。Android標準自動バックアップは無効にし、アプリ内JSONバックアップに一本化しています。復元時は内容を検証し、旧設定のアラーム・通知を掃除してから新設定を予約します。一時的な「出した」「今回は通知不要」「30分後」状態はバックアップしません。

## 小型スマホ向けUI

- 画面左右は12dp中心、カード内は12〜14dp中心
- 横スクロール前提の画面なし
- 小型FAB、TextButton、ダイアログで常設ボタンを削減
- システムバーの安全領域を確保
- ウィジェット最小幅140dp / 高さ64dp

## Android側の制限

- 正確なアラーム特別アクセスがない場合、Androidの省電力制御で通知時刻が遅れることがあります。
- ユーザーがアプリを強制停止すると、OS仕様上バックグラウンド通知は止まります。
- OS設定で通知を完全にOFFにした状態をアプリ側から強制的にONへ戻すことはできません。
- 正確なアラーム特別アクセスをOS設定で取り消すと、Androidが既存の正確なアラームを取り消すことがあります。アプリを次に開くと通常アラームへ再構築します。

## 開発環境

- Kotlin / Jetpack Compose / Material 3
- minSdk 26
- targetSdk / compileSdk 36
- Android Gradle Plugin 8.10.1
- Gradle 8.11.1
- JDK 17
- versionCode 4 / versionName 1.3.0

## ビルド

Android StudioでGradle Sync後、`app` を実行してください。CLIでは以下です。

```bash
./gradlew assembleDebug
```

このソースの `gradlew` / `gradlew.bat` は `gradle-wrapper.properties` のGradleバージョンとSHA-256を読み取り、必要な配布ZIPを取得・検証して起動する方式です。
